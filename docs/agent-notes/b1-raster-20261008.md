## Approved implementation contract (plan before edits)

The control owner accepts ordered operations identified by session, sequence,
operation ID, revision and target. GUI active/provisional buffers remain private.
Published resources use immutable premultiplied sRGB RGBA, bottom-up, explicit
stride/dimensions and a Windows shared-memory lease. Metadata stays in JSON;
pixels do not. Resource consumers cover current/history, queued persistence and
active readers. Capacity failure precedes acceptance; history's existing caps
and the 512 MiB durable artwork limit remain.

Completed operations and recovery are ordered and duplicate-safe. Unknown ACKs
are reconciled, not rolled back as certain rejection. Renderer resource upload
uses the existing ImageLayers path independently of PNG/decode jobs. Persistence
completion records its own resource's durability and never replaces current
pixels. Save pins values, resources and Qt metadata, secures dependencies, and
atomically replaces JSON once. Failure preserves previous saves and accepted
content; memory-only content is not crash recovery.

## Implemented candidate

ControlOwner remains the sole document/history authority. `raster_resources.py`
provides immutable binary snapshots, owner lease admission, background PNG jobs,
the duplicate ledger and revision-pinned portable saves. Qt submits completed
commands on one ordered executor. The existing ImageLayers uploader can consume
runtime pixels without waiting for a PNG or still/model decoder. Completed images
retain their order through the existing Studio pipe; replaceable previews keep
coalescing. Renderer ACK, PNG durability and owner acceptance are separate.

Drawing stays on the SAME selected editable layer; pixel algorithms in artwork.py
and composition/history mathematics are unchanged. First-stroke recovery retains
an immutable original-source lease. Accepted edits remain in scoped history while
PNG writes are pending or failed. A late callback records durability only. Fill,
cut/extract/paste and shared generated-raster completions use the same adapter.
Ordinary/Group locks, local drawing and structural recovery scopes, direct tools,
settings, docking, stable row IDs and source-coordinate semantics remain.

Save pins owner values, revision/session and Qt drafts; failed working PNGs can
be secured directly in Save As dependencies. Copy/JSON failure retains the prior
valid session and its requested checkpoint. Retry saving offers a destination for
a failed retained checkpoint. New edits do not substitute for the pinned revision
or become marked saved. Completed old-session saves cannot change the current
destination/saved marker. Session switches retire old resource lookup keys while
old write/save/output consumers retain leases; loaded portable paths keep their
stable stored asset IDs. Old GUI decode/cache entries are cancelled/cleared.

Capacity is explicit: client 16 commands; GUI 128 MiB transfer leases; owner
384 MiB retained snapshots, 16 persistence reservations/256 MiB pending bytes;
one PNG worker and one save worker; four retained checkpoints and 16 terminal
save outcomes. Existing history, cache, GL and 512 MiB artwork-store limits remain.
Allocation/queue failures reject before history and release producer reservations.
The first original-source snapshot is included in retained-byte accounting.
No dependencies were added. No new renderer, C++ core or parallel inspector exists.
